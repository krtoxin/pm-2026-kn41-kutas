## 2. Як рахувалася симуляція

| Поле | Значення |
| --- | --- |
| Інструмент | власний скрипт Python |
| Прогонів | 10 000 на кожен сценарій |
| Що тягнеться випадково | velocity одного з моїх двох спринтів, 17 або 9, з однаковою ймовірністю |
| Як рахується дата прогнозу | для сценарію «весь перший реліз» кінець спринта 1 (2026-10-22) плюс (P - 1) × 14 днів, для сценарію залишку кінець спринта 2 (2026-10-29) плюс P × 14 днів |

Скрипт, за яким прогін можна повторити:

```python
import random, math

def simulate(remaining, velocity, runs=10000, seed=2026):
    rng = random.Random(seed)
    results = []
    for _ in range(runs):
        left, sprints = remaining, 0
        while left > 0:                     # поки лишились points
            left -= rng.choice(velocity)    # випадковий спринт з історії
            sprints += 1
        results.append(sprints)
    results.sort()
    p50 = results[math.ceil(0.50 * runs) - 1]   # перцентилі в цілих спринтах
    p85 = results[math.ceil(0.85 * runs) - 1]
    return p50, p85

mine = [17, 9]
print(simulate(47, mine))   # весь перший реліз -> (4, 5)
print(simulate(21, mine))   # залишок після двох спринтів -> (2, 3)

ref = [21, 17, 26, 14, 23, 6, 28, 12, 22, 25, 18, 9]   # навчальні дані курсу
print(simulate(220, ref), simulate(220, ref[0:2]), simulate(220, ref[4:6]))
```

Перевірка, що цикл рахує правильно: з іншим зерном генератора (seed) числа ті самі, а залишок 21 при velocity 17 і 9 справді закривається за 2 спринти, якщо хоч один із них дав 17, і за 3, якщо обидва дали 9, тобто P85 = 3 очікуваний.

## 4. Прогноз проти критичного шляху з ЛР7

| Джерело дати | Дата першого релізу |
| --- | --- |
| План ЛР7, `target_date` рядка REL-1 у `lr07_wbs/roadmap.csv` | 2027-02-04 |
| Прогноз P85, `forecast.csv` | 2026-12-10 |
| Строк мого варіанта датою: старт робіт з розділу 4 `lr07_wbs/README.md` плюс строк у тижнях | 2027-02-05 (2026-10-19 плюс 16 тижнів) |

Чому дати різні: прогноз вийшов майже на два місяці раніше за план, тобто навпаки до звичного. Причина в тому, що два методи міряють різну роботу. Мої спринти закривають історію на рівні ескізу і перевірених критеріїв приймання (так записано в `lr11_risks_quality/dod.md`), а план ЛР7 рахує повну роботу команди: розробку модулів, тестування, міграцію даних і приймання із замовником. До того ж спринти почались 09.10, раніше за дату старту робіт у плані. Тож прогноз відповідає на питання «коли всі історії першого релізу будуть описані й перевірені на ескізах», а план на питання «коли сервіс прийме замовник». Ближчою до правди для дати релізу я вважаю дату плану.

Що я з цим роблю: обсяг не ріжу, дату не рухаю і склад команди не обговорюю, бо жоден із двох методів не показує, що ми не встигаємо до строку варіанта. Раніше закінчена робота над історіями дає запас на найризиковіших місцях плану: погодження обсягу T-05 і доступ до входу через акаунт академії (R-12) можна почати, щойно історії S-17-S-19 пройдуть DoD, а не чекати старту робіт.
